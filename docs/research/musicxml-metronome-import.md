# Research: MusicXML metronome import behavior

**Scope:** Research only. Importer behavior is pinned to the latest official releases checked on 2026-10-14: MuseScore 4.7.5 and LilyPond 2.26.0. Claims describe importer source, not a runtime rendering test.

## Normative MusicXML model

MusicXML 4.0 distinguishes ordinary metronome marks from metric relationships. `<beat-unit>` plus `<per-minute>` represents a regular mark; `<beat-unit-dot>` annotates the note value. `<metronome-note>` plus `<metronome-relation>` describe metric modulations and other note-to-note relationships, such as swing markings. The specification describes their meaning but does not require applications to support every form. ([`<metronome>`](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/metronome/), [`<beat-unit>`](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/beat-unit/), [`<beat-unit-dot>`](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/beat-unit-dot/), [`<metronome-note>`](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/metronome-note/), [`<metronome-relation>`](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/metronome-relation/), [`<per-minute>`](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/per-minute/))

## Importer comparison

| MusicXML form | MuseScore 4.7.5 | LilyPond 2.26.0 (`musicxml2ly`) |
| --- | --- | --- |
| `<beat-unit>` + `<per-minute>` | Builds displayed tempo text from the note value and number. When the per-minute value parses numerically, converts that value to quarter-note tempo using the beat-unit duration; this calculated tempo is used if the direction lacks `<sound tempo="...">`. ([parser](https://github.com/musescore/MuseScore/blob/v4.7.5/src/importexport/musicxml/internal/import/importmusicxmlpass2.cpp#L5600-L5664), [fallback](https://github.com/musescore/MuseScore/blob/v4.7.5/src/importexport/musicxml/internal/import/importmusicxmlpass2.cpp#L3489-L3494)) | Converts the first beat unit and per-minute value into a tempo mark. BPM must parse as an integer; invalid values produce a warning and are set to zero. ([converter](https://github.com/lilypond/lilypond/blob/v2.26.0/scripts/musicxml2ly.py#L2881-L2968)) |
| `<beat-unit-dot>` | Displays a dotted note value, but the parser calls `setDots(1)`: repeated dots are not accumulated, so multiple augmentation dots are not preserved. ([parser](https://github.com/musescore/MuseScore/blob/v4.7.5/src/importexport/musicxml/internal/import/importmusicxmlpass2.cpp#L5620-L5633)) | Counts each consecutive `<beat-unit-dot>` on either side of a note-equivalence mark, preserving multiple dots. ([converter](https://github.com/lilypond/lilypond/blob/v2.26.0/scripts/musicxml2ly.py#L2920-L2947)) |
| Two `<beat-unit>` values (note = note equivalence) | Renders both duration values as tempo text. This branch does not calculate `m_tpoMetro`; it uses a separate `<sound tempo>` if present, otherwise this source path supplies no calculated playback tempo for the equivalence. ([parser](https://github.com/musescore/MuseScore/blob/v4.7.5/src/importexport/musicxml/internal/import/importmusicxmlpass2.cpp#L5620-L5656), [text and tempo assignment](https://github.com/musescore/MuseScore/blob/v4.7.5/src/importexport/musicxml/internal/import/importmusicxmlpass2.cpp#L3520-L3532)) | Handles a second `<beat-unit>` as the new duration and stores it on the tempo mark; this simple note-to-note equivalence is supported. ([converter](https://github.com/lilypond/lilypond/blob/v2.26.0/scripts/musicxml2ly.py#L2937-L2968)) |
| `<metronome-note>` + `<metronome-relation>` | Explicitly skips both elements with no warning: `skipLogCurrElem()` only skips the XML element, and its logging call is commented out. As a result, their note shapes and relationship are not used to build the imported text or tempo. ([parser](https://github.com/musescore/MuseScore/blob/v4.7.5/src/importexport/musicxml/internal/import/importmusicxmlpass2.cpp#L5614-L5618), [skip helper](https://github.com/musescore/MuseScore/blob/v4.7.5/src/importexport/musicxml/internal/import/importmusicxmlpass2.cpp#L1968-L1976)) | Complex metronome-note relationships are marked TODO and issue a warning that they are not implemented. The importer does not translate the relation into a note-to-note tempo mark. ([converter](https://github.com/lilypond/lilypond/blob/v2.26.0/scripts/musicxml2ly.py#L2949-L2976)) |

## Limits

This is source inspection, not an executed import/render comparison. MuseScore source establishes that the displayed tempo object is created when direction text is recognized as tempo text, and that its calculated tempo comes from `<sound tempo>` or the simple beat-unit/per-minute fallback; it does not establish the exact glyph appearance for every font or engraving setting. LilyPond's warning establishes unsupported conversion of complex relations, not the precise appearance of any partially returned event. Neither source evidence should be generalized beyond the cited releases.
