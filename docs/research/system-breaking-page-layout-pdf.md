# Research: System breaking, page layout, and PDF output

Status: comparative research only. This report does not adopt either product's engraving rules or decide the renderer's page/overflow policy.

Context: [Wayfinder research issue #63](https://github.com/mwilsoncoding/dozenal-music-engraving-renderer/issues/63), child of [plan issue #58](https://github.com/mwilsoncoding/dozenal-music-engraving-renderer/issues/58). The ticket asks how MuseScore and LilyPond break scores into Systems, compose Systems onto Pages, handle geometry/overflow, and emit PDF, compared with the proposed staged pipeline: Systems -> Pages -> PDF. Existing [horizontal-spacing research](lilypond-musescore-spacing.md) remains separate; this report does not repeat its spacing comparison.

## Comparison

### LilyPond

**User-facing controls.** The notation reference separates line breaking from page breaking. Users can permit or prevent a system break at a location with `\break` and `\noBreak`, and force or prevent a page break with `\pageBreak` and `\noPageBreak`; paper and layout settings control such things as line width, page dimensions, margins, and ragged versus justified systems/pages. The manual also documents selectable page-breaking strategies and settings for vertical system spacing. ([Notation Reference](https://lilypond.org/doc/v2.25/Documentation/notation/spacing-issues.html), sections “Page layout” and “Breaks”; [version-pinned manual source](https://github.com/lilypond/lilypond/blob/e01b9d8b7d4fc0d8a3ca033c74d2bbbeeeb85cfd/Documentation/en/notation/spacing.itely#L66-L145), [break controls](https://github.com/lilypond/lilypond/blob/e01b9d8b7d4fc0d8a3ca033c74d2bbbeeeb85cfd/Documentation/en/notation/spacing.itely#L1531-L1800).)

**Internal boundary.** System breaking is a distinct line-division problem: the constrained breaker evaluates candidate divisions using line dimensions and break penalties, and its solver searches system counts/configurations. The source comments describe a dynamic-programming recurrence for line-break choices; when it cannot find a satisfying division, the implementation warns and falls back to one line. ([`constrained-breaking.cc`](https://github.com/lilypond/lilypond/blob/e01b9d8b7d4fc0d8a3ca033c74d2bbbeeeb85cfd/lily/constrained-breaking.cc#L37-L50), [solver/fallback](https://github.com/lilypond/lilypond/blob/e01b9d8b7d4fc0d8a3ca033c74d2bbbeeeb85cfd/lily/constrained-breaking.cc#L179-L221).)

Page breaking is a subsequent, distinct stage. `Page_breaking` requests candidate system configurations from the line breaker, evaluates how systems are distributed across pages, and returns pages from the chosen systems-per-page result. `Optimal_page_breaking` can seek a suitable page count or honor a forced count; it also considers system counts around the line breaker's ideal. This is evidence for a Systems-to-Pages boundary, not a requirement to copy LilyPond's algorithms. ([`page-breaking.cc`](https://github.com/lilypond/lilypond/blob/e01b9d8b7d4fc0d8a3ca033c74d2bbbeeeb85cfd/lily/page-breaking.cc#L29-L59), [`optimal-page-breaking.cc`](https://github.com/lilypond/lilypond/blob/e01b9d8b7d4fc0d8a3ca033c74d2bbbeeeb85cfd/lily/optimal-page-breaking.cc#L41-L113), [final page construction](https://github.com/lilypond/lilypond/blob/e01b9d8b7d4fc0d8a3ca033c74d2bbbeeeb85cfd/lily/optimal-page-breaking.cc#L131-L153).)

**Geometry and overflow.** Paper geometry and score-layout geometry are configurable separately: page dimensions/margins live in paper settings, while line width and system spacing constrain the music layout. The cited no-solution fallback concerns system division; it is not a general promise to scale, clip, or safely fit arbitrary oversized marks or pages. The manual exposes layout choices, but the renderer must still define its own behavior when a system or indivisible item cannot fit. ([Notation Reference](https://lilypond.org/doc/v2.25/Documentation/notation/spacing-issues.html); pinned [`spacing.itely`](https://github.com/lilypond/lilypond/blob/e01b9d8b7d4fc0d8a3ca033c74d2bbbeeeb85cfd/Documentation/en/notation/spacing.itely#L66-L145), [page-breaking variables](https://github.com/lilypond/lilypond/blob/e01b9d8b7d4fc0d8a3ca033c74d2bbbeeeb85cfd/Documentation/en/notation/spacing.itely#L849-L950).)

**PDF output.** The command-line manual documents PDF as the default output. In the pinned manual, the PostScript backend is also used for PDF and its PostScript data is post-processed by Ghostscript's `ps2pdf`; SVG has a separate backend. Thus PDF generation consumes engraving output but is not itself the system/page-breaking policy. ([Running LilyPond](https://lilypond.org/doc/v2.25/Documentation/usage/running-lilypond.html); pinned [output-format options](https://github.com/lilypond/lilypond/blob/e01b9d8b7d4fc0d8a3ca033c74d2bbbeeeb85cfd/Documentation/en/usage/running.itely#L438-L460), [backend behavior](https://github.com/lilypond/lilypond/blob/e01b9d8b7d4fc0d8a3ca033c74d2bbbeeeb85cfd/Documentation/en/usage/running.itely#L555-L573).)

### MuseScore Studio

**User-facing controls.** In page view, MuseScore applies system and page breaks automatically from Page settings and Style, while allowing users to insert manual system, page, and section breaks; the handbook describes locks, layout stretch, system breaks, and page breaks as editing controls. PDF is one of the user-selectable score export formats. ([Systems and horizontal spacing](https://musescore.org/en/handbook/4/systems-and-horizontal-spacing), [Pages and vertical spacing](https://musescore.org/en/handbook/4/pages-and-vertical-spacing), [Score size and spacing](https://musescore.org/en/handbook/4/score-size-and-spacing), [File export](https://musescore.org/en/handbook/4/file-export).)

**Internal boundary.** `SystemLayout::collectSystem` targets the configured printable width, adds measures, and updates horizontal spacing. When a multi-measure system grows past that target and the preceding measure is not marked no-break, it removes the last measure and ends the system. In page/system view, explicit page, line, section, and system-lock boundaries also end system collection. ([`systemlayout.cpp`](https://github.com/musescore/MuseScore/blob/ac9d3bcd3df7a19d16d7ef505db9e2b54235c022/src/engraving/rendering/score/systemlayout.cpp#L123-L127), [width overflow and rollback](https://github.com/musescore/MuseScore/blob/ac9d3bcd3df7a19d16d7ef505db9e2b54235c022/src/engraving/rendering/score/systemlayout.cpp#L188-L207), [explicit break conditions](https://github.com/musescore/MuseScore/blob/ac9d3bcd3df7a19d16d7ef505db9e2b54235c022/src/engraving/rendering/score/systemlayout.cpp#L229-L280).)

`PageLayout::collectPage` positions systems using the page's top/bottom margins, system heights, minimum inter-system distance, and header/footer extensions. It starts a new page for an explicit page break or when the next system plus required spacing would reach the usable page bottom. This is a vertical page-packing boundary separate from measure-to-system collection. The cited path does not establish a universal policy for a single system taller than the usable page. ([`pagelayout.cpp`](https://github.com/musescore/MuseScore/blob/ac9d3bcd3df7a19d16d7ef505db9e2b54235c022/src/engraving/rendering/score/pagelayout.cpp#L128-L147), [system placement and page-fit test](https://github.com/musescore/MuseScore/blob/ac9d3bcd3df7a19d16d7ef505db9e2b54235c022/src/engraving/rendering/score/pagelayout.cpp#L201-L205), [page-break decision](https://github.com/musescore/MuseScore/blob/ac9d3bcd3df7a19d16d7ef505db9e2b54235c022/src/engraving/rendering/score/pagelayout.cpp#L240-L275).)

**Geometry and overflow.** The handbook exposes page size, margins, scaling/staff-space settings, and vertical layout adjustments. The source's system collector compares measured system width with printable width and backs out the last measure where a break is allowed; that does not prove what happens for a single overwide measure or a locked group that cannot be divided. Page collection checks room for the next system, but the cited code alone does not show clipping, global scaling, or handling for a page containing one over-height system. Those remain renderer policy choices, not facts to infer from a fit test. ([Score size and spacing](https://musescore.org/en/handbook/4/score-size-and-spacing); [`systemlayout.cpp`](https://github.com/musescore/MuseScore/blob/ac9d3bcd3df7a19d16d7ef505db9e2b54235c022/src/engraving/rendering/score/systemlayout.cpp#L188-L207); [`pagelayout.cpp`](https://github.com/musescore/MuseScore/blob/ac9d3bcd3df7a19d16d7ef505db9e2b54235c022/src/engraving/rendering/score/pagelayout.cpp#L240-L275).)

**PDF output.** The handbook documents PDF through the score export workflow. At the pinned source, `PdfWriter` creates a `QPdfWriter`, sets resolution and page size from notation painting, sets zero PDF page margins, and calls `paintPdf`; this is a PDF export adapter that consumes already-laid-out pages. Printing is a distinct path through `QPrinter` and `paintPrint`. ([File export](https://musescore.org/en/handbook/4/file-export); [`pdfwriter.cpp`](https://github.com/musescore/MuseScore/blob/ac9d3bcd3df7a19d16d7ef505db9e2b54235c022/src/importexport/imagesexport/internal/pdfwriter.cpp#L45-L78), [PDF page setup](https://github.com/musescore/MuseScore/blob/ac9d3bcd3df7a19d16d7ef505db9e2b54235c022/src/importexport/imagesexport/internal/pdfwriter.cpp#L144-L150), [`printprovider.cpp`](https://github.com/musescore/MuseScore/blob/ac9d3bcd3df7a19d16d7ef505db9e2b54235c022/src/print/internal/printprovider.cpp#L35-L75).)

## Transferable concepts, not product decisions

1. Keep system formation and page composition as separate stages with explicit inputs/outputs. A page composer can place complete Systems using page geometry without owning measure-to-system decisions; both source trees have this architectural boundary. ([LilyPond page breaking](https://github.com/lilypond/lilypond/blob/e01b9d8b7d4fc0d8a3ca033c74d2bbbeeeb85cfd/lily/page-breaking.cc#L29-L59), [MuseScore page collection](https://github.com/musescore/MuseScore/blob/ac9d3bcd3df7a19d16d7ef505db9e2b54235c022/src/engraving/rendering/score/pagelayout.cpp#L119-L147).)
2. Represent manual break/keep-together constraints in the layout model, separately from automatically chosen breakpoints. MuseScore exposes break objects and locks; LilyPond exposes explicit break/no-break commands. Their exact semantics need not be copied. ([LilyPond break controls](https://github.com/lilypond/lilypond/blob/e01b9d8b7d4fc0d8a3ca033c74d2bbbeeeb85cfd/Documentation/en/notation/spacing.itely#L1540-L1565), [MuseScore break conditions](https://github.com/musescore/MuseScore/blob/ac9d3bcd3df7a19d16d7ef505db9e2b54235c022/src/engraving/rendering/score/systemlayout.cpp#L229-L280).)
3. Make the printable system rectangle, page rectangle, margins, and inter-system spacing explicit geometry. Perform fit decisions against those values rather than relying on the PDF backend to discover layout overflow. ([MuseScore system-width target](https://github.com/musescore/MuseScore/blob/ac9d3bcd3df7a19d16d7ef505db9e2b54235c022/src/engraving/rendering/score/systemlayout.cpp#L123-L127), [page fit calculation](https://github.com/musescore/MuseScore/blob/ac9d3bcd3df7a19d16d7ef505db9e2b54235c022/src/engraving/rendering/score/pagelayout.cpp#L240-L275), [LilyPond page settings](https://github.com/lilypond/lilypond/blob/e01b9d8b7d4fc0d8a3ca033c74d2bbbeeeb85cfd/Documentation/en/notation/spacing.itely#L66-L145).)
4. Let PDF serialization consume positioned page content. Decide separately which vector backend, units/resolution, metadata, font handling, and page-size behavior the renderer requires. ([LilyPond PDF backend](https://github.com/lilypond/lilypond/blob/e01b9d8b7d4fc0d8a3ca033c74d2bbbeeeb85cfd/Documentation/en/usage/running.itely#L555-L573), [MuseScore PDF writer](https://github.com/musescore/MuseScore/blob/ac9d3bcd3df7a19d16d7ef505db9e2b54235c022/src/importexport/imagesexport/internal/pdfwriter.cpp#L45-L78).)

## Decisions left open for this renderer

- Page size/orientation, margins, staff/system scale, and whether there are headers/footers.
- Automatic system-break objective, allowed break locations, manual break/keep-together representation, and whether the last system is justified.
- How to handle content too wide for a system or too tall for a page: allow overflow, break at another boundary, scale, clip, warn, or return an error. In particular, define behavior for one indivisible overwide measure and one over-height system.
- Whether page composition can rebalance systems across adjacent pages, and how explicit page breaks constrain that process.
- PDF backend and conformance needs: vector output, page size/units, resolution for any raster content, fonts, metadata, and multi-page guarantees.

The pinned implementations are feature-rich references, not a specification for this renderer's dozenal glyph dimensions or overflow semantics. No common score was rendered in both products, and no performance or visual-quality comparison was attempted. The MuseScore handbook is the current Handbook 4 content, not an archived manual snapshot for v4.5.2; implementation claims are instead tied to the cited source commit. No renderer source, tests, fixtures, or issue state were changed.
