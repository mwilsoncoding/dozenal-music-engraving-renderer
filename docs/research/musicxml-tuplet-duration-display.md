# Research: MusicXML tuplet duration and display semantics

**Context:** Wayfinder research issue [#114](https://github.com/mwilsoncoding/dozenal-music-engraving-renderer/issues/114). Research only; this report makes no renderer policy recommendation.

## Findings

### MusicXML 4.0 normative model

`<time-modification>` and `<tuplet>` are related but distinct. `<time-modification>` describes the cumulative sounding-duration effect relative to the written `<type>` and `<dot>`; `<tuplet>` supplies graphical tuplet notation in addition to that sound data. The reference defines `actual-notes` as the number played in the time normally occupied by `normal-notes`, and `normal-notes` as the converse. Thus a 3:2 triplet has a duration factor of $2/3$ relative to its written note value, not $3/2$. The note's `<duration>` remains the encoded sounding duration in divisions. ([`time-modification`](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/time-modification/), [`actual-notes`](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/actual-notes/), [`normal-notes`](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/normal-notes/), [`duration`](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/duration/))

The XSD makes `<time-modification>` optional on a note, and its content model requires `actual-notes` followed by `normal-notes`; optional `normal-type` and zero or more `normal-dot` follow. `<notations>` is also optional, and its repeated choice permits zero or more `<tuplet>` marks. There is no XSD co-occurrence rule linking the two elements. ([MusicXML 4.0 XSD](https://www.w3.org/2021/06/musicxml40/listings/musicxml.xsd/))

Consequences of that structure:

- Ratio without a tuplet mark is structurally valid. It supplies timing information but no graphical tuplet span/label instruction.
- A tuplet mark without a `<time-modification>` is structurally valid. It supplies a display span, but not the dedicated cumulative ratio data; note `<duration>` still gives sounding duration, while deriving the intended ratio from note values is not guaranteed by these elements.
- A present `<time-modification>` missing either required child is XSD-invalid. That malformed partial form has no normative ratio interpretation. Both children are typed as `xs:nonNegativeInteger`; the XSD therefore admits zero lexically even though a zero count cannot define a usable duration ratio. The reference and schema do not state an application recovery rule.
- `<tuplet>` contains independent graphical controls such as bracket, line shape, placement, `show-number`, and `show-type`; absent bracket is implementation-dependent. It can also carry optional actual/normal display number/type children. ([`tuplet` reference](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/tuplet/), [MusicXML 4.0 XSD](https://www.w3.org/2021/06/musicxml40/listings/musicxml.xsd/))

Nested tuplets use cumulative sounding ratios on each note plus separate numbered graphical spans. A note can contain at most one `<time-modification>` in the XSD, while its `<notations>` can contain repeated `<tuplet>` elements. The official nested example starts with an outer 3:2 ratio and `number="1"`; notes in the inner level carry cumulative 9:4 and a second `number="2"` span. The schema documentation explicitly says both elements are needed for accurate nested/complex notation. ([Nested example](https://www.w3.org/2021/06/musicxml40/musicxml-reference/examples/tuplet-element-nested/), [MusicXML 4.0 XSD](https://www.w3.org/2021/06/musicxml40/listings/musicxml.xsd/), [`time-modification` reference](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/time-modification/))

### Export and engraving

LilyPond's pinned `musicxml2ly` path imports MusicXML into LilyPond notation; this report found no corresponding MusicXML exporter in that path, so a LilyPond MusicXML round-trip/export comparison is not applicable here. Its handling above is source inspection, not an executed render. The conversion preserves bracket/number/type options found on explicit marks, but nested grouping is marked unsupported. ([`musicxml2ly.py`](https://github.com/lilypond/lilypond/blob/e01b9d8b7d4fc0d8a3ca033c74d2bbbeeeb85cfd/scripts/musicxml2ly.py#L697-L802), [parser classes](https://github.com/lilypond/lilypond/blob/e01b9d8b7d4fc0d8a3ca033c74d2bbbeeeb85cfd/python/musicxml.py#L977-L1046))

MuseScore exports duration ratios and graphical spans separately: its exporter writes `actual-notes`/`normal-notes` in `<time-modification>` when the ratio is non-1:1, and writes numbered `<tuplet type="start|stop">` marks from its internal tuplet model. Nested levels get numbered display marks; ratio details are emitted for nested starts where needed. Import does not preserve the incoming tuplet's display children, so source indicates normalization rather than exact round-trip preservation of those attributes. ([ratio writer](https://github.com/musescore/MuseScore/blob/ac9d3bcd3df7a19d16d7ef505db9e2b54235c022/src/importexport/musicxml/internal/musicxml/export/exportmusicxml.cpp#L4246-L4272), [display writer](https://github.com/musescore/MuseScore/blob/ac9d3bcd3df7a19d16d7ef505db9e2b54235c022/src/importexport/musicxml/internal/musicxml/export/exportmusicxml.cpp#L2752-L2817), [import handling](https://github.com/musescore/MuseScore/blob/ac9d3bcd3df7a19d16d7ef505db9e2b54235c022/src/importexport/musicxml/internal/musicxml/import/importmusicxmlpass1.cpp#L3270-L3291))

The official MuseScore Handbook 4 documents nested tuplets and independent number/bracket visibility controls, which establishes the user-facing engraving model but is not a frozen v4.5.2 manual. ([Tuplets](https://musescore.org/en/handbook/4/tuplets)) The handbook page is current content retrieved 2026-10-09; implementation claims above are pinned to the v4.5.2 source commit. The LilyPond source commit is v2.25.2; current online manual routing/version was not used as evidence for importer edge cases.

## Ambiguities and limits

- MusicXML permits ratio-only and display-only structures but does not prescribe how an application should infer, synthesize, suppress, or repair the other layer. A valid `<duration>` can still encode sound duration when the ratio is absent, but it cannot restore omitted graphical or ratio metadata by itself.
- The MusicXML schema's nonnegative integer type admits zero for actual/normal counts; applications reject or cannot meaningfully apply such a ratio. The sources reviewed do not specify whether zero should be treated as invalid beyond the schema type.
- Source inspection does not prove exact rendered glyphs, exported files, or error recovery for every malformed score. No test MusicXML documents were run through the pinned binaries, and no cross-application round trip was performed.
- MuseScore Handbook 4 is not version-frozen to MuseScore 4.5.2. Its role here is limited to documented user-facing tuplet display; source behavior is pinned separately.
